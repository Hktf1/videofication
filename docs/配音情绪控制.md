# 配音情绪控制（分段合成）

逐句控制语速、音调、音色和停顿。朗读稿一字不动，另写一份 `朗读稿.演出.txt` 说明「每句怎么说」。

## 为什么不是 SSML

Edge TTS 只接受纯文本：送进去的 `<prosody>`、`<break>` 等标签会被转义后**当字念出来**（实测一句 SSML 念了 21 秒，把 `speak version=... prosody rate=...` 全读了一遍）。微软已对免费接口关闭 SSML。

所以这里的做法是：**一行文字 = 一段，每段单独调用 Edge TTS，裁掉首尾静音，段与段之间插入静音，拼成一条 WAV 后统一编码一次 MP3**。听感上和 SSML 的逐句控制等价。

## 文件

```
episodes/NN-文章/NN-M-章名/
  ├─ 朗读稿.txt          文字本体（唯一来源，对稿、字幕都靠它）
  └─ 朗读稿.演出.txt     怎么说（可选，存在就启用演出模式）
```

- **每章必做**：`朗读稿.演出.txt` 是配音的输入，`npm run check` 和导出检查都会因为缺失而报错（2026-10-24 用户定）
- 演出稿的文字必须和 `朗读稿.txt` **逐字一致**（标点、空白不算），不一致会拒绝生成配音
- 改了朗读稿，记得同步改演出稿；`npm run check` 会校验

## 格式

```
# 井号开头是注释，空行随意

@默认
为什么人总是半途而废？

@停顿 800ms

@低缓
因为人类是一种需要希望的生物。

@音色 云希
一条路逻辑上再正确，只要它不能即时且适量的提供正向反馈，那么再坚实的逻辑，都形同虚设。

@默认 rate=+8% pitch=+2Hz
庞氏骗局，就诞生于此。
```

规则：

- **一行 = 一段（一句）**。段内想要停顿，就把它拆成两行，中间加 `@停顿`
- **换行就是分段**：一句再长也写在同一行，不要为了排版折行，否则会在断行处重新起调
- `@` 指令对它**后面**的文字生效，直到下一条指令
- 以 `@@` 开头的行按正文处理（正文真的要以 @ 开头时用）
- 只读标点的行会被跳过并提示

## 指令

### 预设（只改语速/音调/音量，不换音色）

| 预设 | 语速 | 音调 | 音量 | 适合 |
|------|------|------|------|------|
| `@默认` / `@正常` | +0% | +0Hz | +0% | 大部分叙述 |
| `@沉稳` | -6% | -3Hz | +0% | 结论、严肃陈述 |
| `@低缓` | -8% | -4Hz | -5% | 开场、画面感、留白 |
| `@慢` | -6% | +0Hz | +0% | 需要听清的关键句 |
| `@强调` | -2% | +2Hz | +10% | 重点句 |
| `@激动` | +15% | +3Hz | +0% | 情绪上扬 |
| `@紧张` | +22% | +3Hz | +0% | 慌乱、急促 |
| `@温柔` | -6% | +2Hz | -5% | 安慰、放缓 |
| `@低语` | -8% | -3Hz | -20% | 压低、心理活动 |

预设的幅度（2026-10-24 收窄）是有原因的：

- **语速不超过 -8%**。Edge TTS 的减速是拉长每个字的元音，超过 -10% 开始发糊、拖尾，生出「AI 味」。要更沉，用的是短句、停顿和长屏，不是继续降 rate。
- **音调不超过 ±4Hz**。`pitch` 是整句平移，不是句内重音。幅度一大就变成「整句抬高」，一听就假。重音靠的是前后停顿的落差、前一句的加速、单独成屏。
- 写超出 ±10%（rate）或 ±6Hz（pitch）的自定义值时，`tts` 会给出提示。

### 覆盖单个参数

任何预设后面都可以跟 `key=value`，也可以不套预设直接写：

```
@沉稳 rate=-3%            先套「沉稳」，再把语速改成 -3%
@默认 rate=-5%            等于「正常语速但慢 5%」
@rate=-8% pitch=-3Hz     只改这两个参数，其余保持上一条指令的状态
```

- `rate`：`-50%` ～ `+100%`（0% 正常），实际建议 -8% ～ +8%
- `pitch`：`-50Hz` ～ `+50Hz`（0Hz 正常），实际建议 ±4Hz
- `volume`：`-100%` ～ `+100%`
- `voice`：见下方音色；等价于 `@音色`

### 停顿

```
@停顿 800ms
@停顿 950ms
@停顿 700      不带单位按毫秒
```

- 停顿插在段与段之间；连续两行停顿会合并成一处
- **单处上限 1 秒**（2026-10-24 用户定）：合并后超过 1000ms 由 `npm run check` 判为错误，节奏会散
- 每段合成后会裁掉首尾静音（段首留 30ms、段尾留 50ms），插入静音时已扣掉这 80ms，**写多少就是实际停多少**
- 成片里另有 1.8 秒的空白上限：任何一段没人声的时间（包括章与章拼接处）都不超过 1.8 秒，`script.md` 的停留/转折超出会被自动压短（`engine/src/script/timeline.ts` 的 `MAX_VOICE_GAP`）

### 音色

```
@音色 云希
@音色 zh-CN-XiaoxiaoNeural
```

| 简称 | 音色 ID | 特点 |
|------|---------|------|
| 云健 | `zh-CN-YunjianNeural` | 沉稳（默认） |
| 云希 | `zh-CN-YunxiNeural` | 年轻、亲切 |
| 云扬 | `zh-CN-YunyangNeural` | 新闻播报 |
| 云夏 | `zh-CN-YunxiaNeural` | 少年、活力 |
| 晓晓 | `zh-CN-XiaoxiaoNeural` | 温柔 |
| 晓伊 | `zh-CN-XiaoyiNeural` | 邻家 |
| 晓辰 | `zh-CN-XiaochenNeural` | 清新 |
| 晓涵 | `zh-CN-XiaohanNeural` | 温暖成熟 |

音色一直生效，直到下一条 `@音色`。多角色对话可以靠它实现。

## 命令

```bash
npm run tts -- 02-1 --dry    # 只打印分段表，不调用 TTS、不花钱
npm run tts -- 02-1          # 有演出稿就自动用演出模式
npm run tts -- 02-1 --plain  # 强制忽略演出稿，全文同一套参数
npm run voice -- 02-1        # 后面的对稿、字幕流程不变
```

- `--ssml` 已移除：Edge TTS 不认 SSML，保留它只会生成读标签的废音频
- 分段合成有缓存：`字幕/.tts/` 里按「音色+语速+音调+音量+文字」散列存片段，只重配改过的句子；每次成功后自动清掉没用的缓存
- 段内超过 300 字的会被自动切成几段，用同一套参数合成

## 校验

生成配音前会检查演出稿，`npm run check -- NN-M` 也会检查：

- 文字是否和 `朗读稿.txt` 逐字一致（会指出第几个字开始不一样）
- 指令名、参数名、参数范围、停顿时长是否合法
- 只有标点的行、过长的停顿会给提示

文字不一致时**不会生成配音**，避免对稿和字幕时间整体错位。

## 停顿时分层

停顿是语气的第一杠杆：`rate` 和 `pitch` 是整句级的，改多了立刻变成播音腔；停顿是唯一能落到词与词之间的手段。

**先要知道 TTS 自己会停多久。** 实测（`03-1` 的 9 个片段，-30dB / -40dB 两档阈值）Edge TTS 在段内的标点自带停顿：

| 标点 | 自带停顿 |
|------|----------|
| 逗号、顿号 | 130～420ms |
| 句号、问号、叹号 | **约 700ms** |

所以 `@停顿` 只在**分段处**生效，它要排在句号那 700ms 之上才有层级意义。低于 700 的「停顿」听起来不是停顿，是连读。

| 层级 | 时长 | 用在哪 |
|------|------|--------|
| 段内句号 | 不写，交给 TTS | 一句话说完、同一意思继续；约 700ms |
| 同段换语速 / 换音色 | 700ms | 断行是为了换参数，不是要停顿，保持原来的句距 |
| 段落 | 800～850ms | 一个意思说完、转入下一个意思 |
| 结构转折 | 950～1000ms | 反问之后、结论之前、类比登场之前 |

- 1 秒是硬上限，写 1000 就是实际 1000，不再像以前那样被放大成 2 秒
- 每段合成后会**裁掉首尾静音**（段首留 30ms、段尾留 50ms），插入静音时已扣掉这 80ms，**写在演出稿里的值就是听感上的值**
- 句号后写小于 500ms 的停顿，`tts` 会提示（比自带句号停顿还短）
- 全篇都用上限等于没有重音；大部分分段点用 700～850 就够

想调段内节奏，别靠 `@停顿`（段内写不进去），靠**朗读稿的标点**：逗号和句号之间有 300～550ms 的差距，这是唯一能落到句内的手段。长句里加一个逗号，比在段尾多停 200ms 有效得多。

## 按意群分行（整段合成）

一行文字就是一次 TTS 调用。**逐句分行会让模型每句都重新起调**，听感像一条条念清单；把同一语速的几句话写在一行，模型就能带着上一句的语调往下走。

规则：

- 同一语速、中间不需要停顿的几句话，**写在同一行**，作为一次合成
- 相邻两行参数相同且中间没有 `@停顿` 时，生成时也会自动合并（写在两行只是便于编辑）
- 只有想换语气、换语速，或者想真正停顿的地方，才另起一行
- 段内的句号、逗号由 Edge TTS 自己处理，不要为了「让它喘气」而拆行
- **不要在逗号处断行插停顿**：前半句会带句尾降调、后半句重新起调，那个「换气」听起来像句号。要停在句号、分号或段落边界

代价是一行内的几句共用一套语速和音调。所以取舍是：**要连贯就合并，要逐句变速就拆开**。02 章的止痛药三段就是靠拆开 + 提速做的。

## 调参建议

- **语速跟句子功能走**：铺陈 +3～5%，举例 +3%，结论/意象 -6～-8%，反问 -6～-8%
- **音调只做 ±2～4Hz 的微调**；`@激动`、`@紧张` 留给真正的情绪段落，不要用在论述里
- **大部分句子保持默认**，满篇变调会显得做作
- 停顿按上面的分层表分配，单处不超过 1 秒
- 情绪参考：

| 情绪 | 语速 | 音调 |
|------|------|------|
| 正常叙述 | +0% | +0Hz |
| 沉稳、严肃 | -4% ～ -8% | -2Hz ～ -4Hz |
| 激动、兴奋 | +12% ～ +20% | +2Hz ～ +4Hz |
| 紧张、慌乱 | +18% ～ +25% | +2Hz ～ +4Hz |
| 放松、温柔 | -4% ～ -8% | +0Hz ～ +3Hz |

## 完整示例

```
# 开场：慢、低，留悬念
@低缓
为什么人总是半途而废？

@停顿 950ms

# 主体：正常叙述
@默认
因为人类是一种需要希望的生物。

@停顿 800ms

# 转折句：稍提语速和音调
@默认 rate=+8% pitch=+2Hz
可是，希望一旦断掉——

@停顿 1000ms

# 结论：压慢、压低
@沉稳
手头的事，只要一刻没有希望，就一刻也做不下去。
```

## 工作流程

1. 先按老流程写好、审好 `朗读稿.txt`（原文一字不改，只调标点）
2. 由 Claude 复制它的文字，加指令写成 `朗读稿.演出.txt`（必做：语速按句子功能分，停顿按上面的分层表，单处不超过 1 秒）
3. `npm run tts -- NN-M --dry` 看分段表，确认哪句用了什么参数
4. `npm run tts -- NN-M` 生成 `字幕/配音.mp3`
5. `npm run voice -- NN-M` 照常对稿；有缺段时检查演出稿是不是漏了句子

## 排错

- **文字不一致**：按报错给的位置改演出稿，别改朗读稿
- **某句听起来没变**：看 `--dry` 里该句前面最近的一条 `@` 指令是否生效到了这一行
- **配音里多/少了停顿**：停顿只在段与段之间；句内停顿需要断行
- **改了朗读稿后配音旧了**：重跑 `npm run tts -- NN-M`，只有改动的句子会重新合成
