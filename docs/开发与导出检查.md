# 开发与导出检查

- `npm run typecheck`：检查正式代码及已接入的实验代码。
- 正式动效还须完成下文的[画面验收与版本记录](#画面验收与版本记录)。默认由 Agent 自检分镜后直接实现、检查并打开预览，用户预览后确认本章，不增加分镜确认闸口。仅用户本次明确要求只审分镜时，记录为“分镜待审、实现待制作”，不启动画面实现或渲染。
- `npm test`：验证长文本切分、演出稿（分段情绪）解析和导出检查。
- `npm run check -- 02`：检查稿件格式，草稿允许缺少配音。
- `npm run check -- 02-1 --ready`：检查导出就绪状态。
- `npm run merge -- 02`：合并全片。合并前核对各章编码、分辨率、帧率、音轨参数；加了片尾卡的章节（处理稿头部 `片尾：是`）除最后一章外，末尾片尾卡按 manifest 的 `outroFrames` 裁掉（需重编码视频），默认不加片尾时直接复制；时长与各章合计误差超过 1.5 秒或 0.2% 视为失败；成功后写成片与 `.manifest.json`。
- `npm run auto -- 02`：从原始文章或 --script 用户脚本开始准备，再串起 tts、voice、check --ready、render、merge；机械步骤失败按 `docs/全自动流程.md` 的策略重试，稿件检查失败立即停止。
- `npm run status` / `npm run progress`：每篇附带当前风格。风格取各章 `script.md` 的 `风格：` 字段（不是成片 manifest）：正式动效显示 `v1`，历史纯文字显示 `legacy-text`，各章不一致显示「混合」并逐章标出；所以改过风格但还没重渲的文章会先显示新风格，成片还是旧的。
- `npm run studio`：正式篇目预览。默认优先挂 制作中/ 里的文章，兼容待制作内已有章节；没有在做的就看最近改过的一篇。`npm run studio -- 12`、`-- 12-1`、`-- 制作中`、`-- 待发`、`-- all` 可指定文章、单章、整个抽屉或全部。范围由 `tools/studio.ts` 传给 `engine/src/episodes.ts`，换范围要重启 studio。
- `npm run studio:experiments`：独立实验预览。

正式导出会在开始前检查全部目标；模板稿、缺少完整章节配音、缺少 `朗读稿.演出.txt`、单处停顿超过 1 秒、过期或无效的逐字时间戳、低于 90% 的配音匹配率、缺段、多出内容、无法映射的字幕屏、演出稿（`朗读稿.演出.txt`）与朗读稿文字不一致或有非法指令、V1 章节 `画面.tsx` 引用的节拍在 `script.md` 里没有对应标记，均阻止导出。缺少背景音乐同样阻止导出（没有它会整片是绝对静音，见 `docs/背景音乐.md`）；音效只要求处理稿真正标记出来的那些，未使用的占位文件不影响导出。审核流程沿用 CLAUDE.md；全自动时由 Agent 自检预览，不逐章要求用户确认。

## 画面验收与版本记录

画面标准以[极简动效规范](风格/极简动效.md)为准，覆盖每章及内部独立论证场景。四类检查分别记录，技术通过不代表画面容易理解：

| 检查 | 方法与判断依据 |
|---|---|
| 技术检查 | 运行 `check --ready`，确认制作文件、配音、字幕与节拍等技术条件 |
| 布局检查 | 全分辨率核对锚点、避让、边界和明暗，再在 960×540 核对主体、标签、方向与断裂；抽帧用于这一层 |
| 动态检查 | 带真实配音与 BGM、1x 连续播放完整章节，核对章首空白、关键落点、对象和位置连续性、退场及结果保持；允许多屏保持，章内不要求一律清场 |
| 理解检查 | 关键帧能指认对象；连续片段能说明哪个对象发生什么变化、表达什么关系；画面确实帮助理解对比、过程或关系，没有额外的符号猜测负担 |

理解检查先据关键帧与带当屏字幕、真实旁白的连续片段描述对象、变化和关系，再与分镜目标核对，不能用分镜解释补足。对象无法指认、变化含义说不清、只能复述字幕却无法解释图形作用，或须额外讲解符号才懂，均记待修。有未读分镜的审阅者时做独立复核；同一 Agent 自检须如实注明，不冒充盲读，也不新增用户分镜确认。

同步对比用于找差异，可读性与节奏看独立版本；分段预览不能证明章首空白，单帧不能证明动态关系。播放明显掉帧时，记录实际条件，将未看清的流畅性与精确落点留为待复核；审阅仍默认使用 Studio，不自行渲染预览视频替代。

验收记在版本目录的 `修改意见.md`，按章节及场景列出技术、布局、动态、理解各自的“待审 / 通过 / 待修”，记录审阅者、自检或独立复核、时间、播放范围与方式、实际理解描述、未解决问题，以及稿件、声音、时间戳、画面和所依赖组件、样式的摘要或版本快照。关联输入改变后复核受影响场景；仅搬目录或修改无关备注不使验收失效。历史三类记录不自动补记为理解通过。

这是正式制作要求：渲染、合并及移入待发前由 Agent 核对当前版本的验收记录，全自动仍不增加逐章询问。当前正式 `check --ready`、`render`、`merge` 和 `auto` 尚未自动强制核验这些记录及其失效状态；独立实验的门槛原型未接入正式命令，不得把文档要求写成已实现的程序能力，也不追补历史成片为“已通过”。

## 成片记录与环境

每次成功导出会在 MP4 旁生成 `.manifest.json`，记录输入文件 SHA-256、引擎源码摘要、依赖锁文件摘要、风格季和导出时间。它用于识别输入版本，不代替原始素材备份，也不会追溯补写已有成片。全片合并会另行生成 `.manifest.json`，记录各章成片的 SHA-256、时长、风格和 ffmpeg 版本。

渲染若在混音阶段报 `Error opening output …\remotion-audio-mixing\0.wav: No such file or directory`，是 Remotion 的系统临时目录没能建立（`%TEMP%` 路径含中文或被清理）。把 `TMPDIR`、`TMP`、`TEMP` 指向纯 ASCII 目录后重跑即可：

```bash
TMPDIR=D:/rtmp TMP=D:/rtmp TEMP=D:/rtmp npm run render -- 03-3
```

未完成的 `engine/src/episodes/02-1-Full.tsx.draft` 缺少 Stage 组件，暂不参与编译或实验入口，原内容保留，恢复开发前需补全依赖。其他实验通过 `engine/src/experiment-index.ts` 进入。

本机 ASR 路径保持不变。Git 忽略依赖、备份、输出和大型素材；这些素材需单独保留备份。

用户脚本导入后，检查原稿快照摘要、台词完整性和处理稿摘要；不得按文章改写用户台词。新成片写 styleId: motion，历史 v1/v2 不带此标识时按纯文字识别，不能误拼为动效。
