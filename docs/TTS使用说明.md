# Edge TTS 自动配音使用说明

## 前置要求

确保已安装 Python 的 `edge-tts` 包：

```bash
pip install edge-tts
```

检查是否安装成功：

```bash
edge-tts --version
```

## 基本流程

### 1. 准备朗读稿

在 `episodes/NN-文章/NN-M-章名/朗读稿.txt` 中准备好调整过标点的文本（原文一字不改）。`npm run chapters` 会把该章原文预填进这个文件，Claude 再按口播调到合适。

### 2. 生成配音

```bash
npm run tts -- 01-1
```

这会：
- 读取该章的 `朗读稿.txt`
- 调用 Edge TTS（云健音色）生成语音
- 输出到该章的 `字幕/配音.mp3`

**配音参数**（在 `tools/tts.ts` 中调整）：
- `VOICE`: `zh-CN-YunjianNeural`（云健，男声沉稳）
- `RATE`: `+0%`（语速，范围 -50% ~ +100%）
- `PITCH`: `+0Hz`（音调，范围 -50Hz ~ +50Hz）

### 2.1 逐句情绪控制（每章必做）

配音前必须写好 `朗读稿.演出.txt`（`npm run check` 缺它会报错）。它用来逐句指定语速、音调、音色或精确停顿，放在章节文件夹里，`npm run tts` 会自动识别：

```
@默认
为什么人总是半途而废？

@停顿 800ms

@低缓
因为人类是一种需要希望的生物。

@音色 云希
一条路逻辑上再正确，只要它不能即时且适量的提供正向反馈，那么再坚实的逻辑，都形同虚设。
```

- 一行 = 一段（一句），**换行就是分段**，不要为了排版把一句折成多行
- `@停顿`、`@低缓`、`@音色 云希`、`@沉稳 rate=-6%` 等指令对它后面的文字生效
- 文字必须和 `朗读稿.txt` 逐字一致，不一致会拒绝生成配音
- `npm run tts -- 01-1 --dry` 只打印分段表，不调用 TTS
- `npm run tts -- 01-1 --plain` 忽略演出稿

完整指令、预设和音色表见 [配音情绪控制.md](配音情绪控制.md)。

Edge TTS **不支持 SSML**（标签会被当字念出来），旧的 `--ssml` 模式已移除。

### 3. 识别和对稿

```bash
npm run voice -- 01-1
```

这会：
- 用 faster-whisper 识别配音，生成 `逐字.json`
- 比对朗读稿和识别结果
- 生成 `校正.srt` 字幕文件

### 4. 逐章处理 script.md

有了配音和逐字时间戳后，开始写 `script.md`，每屏时间会自动对齐。

## 可用音色

Edge TTS 提供多个中文音色，可在 `tools/tts.ts` 中修改 `VOICE`：

**男声：**
- `zh-CN-YunjianNeural`（云健，沉稳）
- `zh-CN-YunxiNeural`（云希，年轻）
- `zh-CN-YunyangNeural`（云扬，新闻播报）

**女声：**
- `zh-CN-XiaoxiaoNeural`（晓晓，温柔）
- `zh-CN-XiaoyiNeural`（晓伊，亲切）
- `zh-CN-XiaochenNeural`（晓辰，自然）

查看所有音色：

```bash
edge-tts --list-voices | grep zh-CN
```

## 语速和音调调整示例

全篇基线在 `tools/tts.ts` 里（只在 `--plain` 或没有演出稿时生效）：

```typescript
const RATE = "+0%";   // 默认不变速
const PITCH = "+0Hz"; // 默认不升降调
```

逐句调整写演出稿，不要靠改这两个常量：

```
@沉稳 rate=-6% pitch=-3Hz
```

建议范围：**语速 -8% ～ +8%、音调 ±4Hz**。Edge TTS 的减速靠拉长元音实现，超过 -10% 开始发糊；`pitch` 是整句平移，幅度大了会变成「整句抬高」的假重音。超出 ±10% / ±6Hz 时 `tts` 会提示。

## 故障排查

### "找不到 edge-tts 命令"

安装 Python 包：
```bash
pip install edge-tts
```

### "TTS 失败：timeout"

朗读稿太长，可能超时。解决方案：
1. 脚本已按 300 字自动分段（演出模式下按行分段），一般不会触发；如仍超时请检查网络
2. 检查网络连接（Edge TTS 需要联网）

### 配音和朗读稿对不上

检查 `npm run voice -- NN` 的输出：
- **缺段**：TTS 可能跳过了某些段落，检查朗读稿格式
- **多出**：识别错误或多识别，可忽略
- **识别错**：同音错字，不影响时间对齐

## 与剪映配音对比

| 方面 | Edge TTS（新） | 剪映（旧） |
|------|---------------|-----------|
| 自动化 | 完全自动 | 需手动复制粘贴 |
| 音色 | 云健等官方音色 | 剪映 AI 音色 |
| 速度 | 几秒（篇幅依赖） | 需打开剪映操作 |
| 质量 | 自然，适合长文 | 类似，稍偏播音腔 |
| 成本 | 免费 | 免费 |

## 已知限制

1. **单次生成限制**：Edge TTS 对单次文本长度有限制（约 10 分钟音频），脚本会自动按 300 字分段再拼接
2. **网络依赖**：需要联网访问微软服务
3. **不支持 SSML**：逐句语速/音调/音色/停顿请用 `朗读稿.演出.txt`（见 [配音情绪控制.md](配音情绪控制.md)）
4. **拼接的停顿长度**：每段合成后会裁掉首尾静音（段首留 30ms、段尾留 50ms），插入静音时扣掉这 80ms，所以演出稿里写多少就是实际停多少
