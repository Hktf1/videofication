# 全自动流程

目标：从一篇原始文章，或“指定文章 + 用户脚本”开始，最后交付完整 MP4。用户要求全自动/不用确认/直接出片时，中途不逐章确认；非全自动继续走 CLAUDE.md 的逐步制作流程。

## 两条输入路径

### 原始文章

文章目录放完整 source.txt 或唯一一份 docx，运行：

```bash
npm run new -- "标题"
npm run auto -- NN
```

正式开工时，auto 先把待制作内的文章文件夹移入 `episodes/制作中/`；`--dry` 不搬文件。`new` 从待制作取入 docx 后直接在制作中目录建文章。无制作章节时，auto 自动准备全文一章的朗读稿、演出稿、字幕切屏和基础动效，再配音出片。首行标题句也是正文，完整保留。已有章节时原样继续，不按原文重新生成稿件。

Agent 从原文制作时先按需要 extract、语义分章、chapters，写演出稿；先配音和对稿，再按真实声音写动态分镜与逐篇定制画面，按[风格规范](风格/极简动效.md)制作，并完成[画面验收与版本记录](开发与导出检查.md#画面验收与版本记录)后跑 auto 完成剩余步骤。分镜由 Agent 自检后直接实现代码，不增加用户分镜确认；逐步制作由用户在预览后确认本章，全自动不增加逐章确认。基础自动画面只使用原稿摘句和阅读进度，不会把文章硬套成固定概率、年份或因果关系；它是当前程序的准备结果，不代表已达到正式交付标准。仅用户本次明确要求先审分镜时，不运行后续实现与渲染。

### 指定文章并提供脚本

```bash
npm run auto -- NN --script "D:/稿件/口播.txt"
npm run auto -- NN --script "D:/稿件/script.md"
```

用户脚本优先于原始文章和已有制作稿。纯口播 txt/md/docx 原样成为朗读稿，字幕只切屏；项目 script.md 原样导入，按现有台词和画面标记制作。同目录的朗读稿、演出稿、画面脚本、画面.tsx 可作为配套输入。画面代码的相对导入会按原位置重新定位，附件留快照；仅更新附件也会建立新版本。已有画面设计但没有代码或标记时，先按设计补齐实现，不用基础画面替代。

新输入进入独立版本（名称包含输入摘要），原稿保存为输入快照，来源与摘要写进制作输入.json。处理稿台词必须和配套朗读稿一致，提供处理稿时不重新写它。没有分镜才补基础画面；用户已有分镜时优先执行用户设计。

只准备文件、不配音不渲染：

```bash
npm run prepare -- NN --script "D:/稿件/口播.txt"
npm run prepare -- NN
```

相同输入再次执行复用已准备的版本；输入改变则生成新版本。显式 --version 只能导入空版本或相同输入版本，不能覆盖其他制作内容。任意分镜表、时间码或画面/旁白混合稿目前需要先无损转换为项目处理稿；无法确定台词边界时停止说明原因，不会按原文另写替代稿。

## 执行顺序

下表区分命令内的自动步骤与 Agent 必做的制作验收；当前 `auto` 不会自动完成定制画面、启动 Studio 或核验动态验收记录。两条输入路径都须由 Agent 补齐这些步骤，全自动不增加逐章确认。

| 步骤 | 执行方式与要求 |
|---|---|
| 输入准备 | 原文生成基础制作文件，或直接导入用户脚本；已有章节不覆盖 |
| 输入校验 | 核对用户原稿快照和台词，受保护的处理稿不能被改写 |
| 配音 tts | 缺失或过期才生成，失败重试 3 次；复用配音需输入摘要和声音配置一致 |
| 对稿 voice | 识别、对稿、生成校正字幕；失败时重配一次再试 |
| 定制画面与验收（Agent） | 按内容选表达（母题可选），分镜自检后实现；允许多屏保持，必要动作同步声音。分别记录技术、布局、动态与理解结果，复用画面时核对记录是否仍适用 |
| check --ready | 与 render 相同的技术检查，失败停止，不自动改写脚本；不代替动态验收 |
| render | 成片缺失或输入更新时渲染，失败重试一次 |
| merge | 按章号排序，核对媒体参数，合并完整 MP4 |
| 归档 | 合并成功后整篇搬进待发；已经在待发/已发时不搬 |

## 参数与恢复

```bash
npm run auto -- NN --dry
npm run auto -- NN --script "D:/稿件/script.md" --dry
npm run auto -- NN --chapter 2
npm run auto -- NN --force
npm run auto -- NN --version 中文-极简动效v1
```

--dry 只读输入并打印计划，不创建版本、不配音、不渲染、不搬文章。--chapter 只做所选章节，不合并不搬。--force 强制配音和渲染，不会重写用户脚本，也不免除当前版本的制作验收。失败修复后重跑同一命令，已完成步骤按新鲜度跳过；输入变化后的验收复核按《开发与导出检查》执行。输入台词已变化时重新导入；不能修改用户处理稿来绕过检查。

## 质量门槛与环境

- 正式风格只有 V1 极简动效，统一外观，允许物体、简化人物、界面、场景和图解；具体以风格规范为准。画面组件或有效画面标记只是技术门槛；历史纯文字不能直接渲染为新 V1。
- 用户脚本的快照、处理稿摘要、台词一致性均受校验；缺输入或格式不支持时不回退到原文自行写稿。
- 配音匹配率至少 90%，无缺段/多出内容，字幕屏可映射且时长有效；演出稿与朗读稿文字一致；模板占位、超字数、错误强调/音效/节拍都会阻止导出。
- BGM 必需；仅要求实际使用的音效素材存在。需要 Edge TTS、ffmpeg/ffprobe、本机 ASR 环境与浏览器。
- .tmp 为渲染临时目录，规避系统中文临时路径；auto/render 各有锁。步骤超时为配音 15 分钟、对稿 30、检查 5、渲染 25、合并 20，超时结束子进程树并走失败处理。
- 合并前核对画面编码、尺寸、帧率、音频编码、采样率和声道；视频流复制、音频 AAC 192k，失败才回退视频重编码。
- 片尾默认不加，要求添加时只写最后一章。旧片多章都有片尾则按 manifest 裁掉前面章的片尾并重编码；无 outroFrames 的旧片不误裁。
- 合并时长误差超过 1.5 秒或 0.2% 视为失败。成功写 manifest 和已整合状态，给出完整成片路径与用时。
- 目标抽屉已有同名文件夹或搬运失败只提示，已生成成片保留。发布后 `npm run move -- NN 已发`。
