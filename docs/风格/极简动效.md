# 极简动效风格

唯一正式风格，程序标识 `v1`（原 V4）；新稿写 `风格：v1`。先读[风格入口](README.md)。

**极简指视觉统一、信息克制、容易理解。** 画面帮助观众看清对象、状态与关系；允许物体、简化人物、手势、界面、场景、图解和动态文字共用一套样式。内容以原稿为依据，不编造案例、数字、结论或因果；用户已有分镜优先。

## 表达选择

先确定这一段要让观众理解什么，再选表现方式：

| 内容 | 优先考虑 |
|---|---|
| 原文已有具体对象或行为 | 直接展示可识别的对象与行为 |
| 操作、使用过程 | 简化界面与操作演示 |
| 两种情况的差别 | 同一对象的前后状态，或共同基准下的并置 |
| 包含、结构、因果、循环 | 有明确名称的简单图解；卡与格、结构架等仅为候选 |
| 原文本身的比喻 | 表现该比喻，检查是否贴合当前关系 |

物体与图解均按内容选择，不优先套路径、概率、时间轴或闸门。抽象概念可直接用短标签命名；线、点、虚线等符号若需要额外解释，优先换成可识别的对象或明确标识。不同段落可用不同表达方式。

## 强制叙事规则

1. **对象稳定。** 每场景先列主体、必要辅助对象、各自含义和可变属性。持续讨论同一对象时，保持外形、名称和位置连续；同一关系只用一个主载体。全篇母题可选，不限制全章物体总数，不为统一道具硬套比喻。
2. **允许保持。** 一屏或连续多屏不动均合规。动作只用于引入当前理解必需的对象、改变状态、建立或改变关系、引导必要的比较；每个动作写明用途。一个完整意思可共用一个动作，不逐词配图，不按动作数量验收。
3. **关键落点同步。** 新对象和标签在首次相关表达处建立，结论和关键变化不抢先；必要动作按真实逐字时间戳同步。时间戳控制落点，不决定动作数量。声音正文直接开始，不增加片头等待。
4. **换场保留语境。** 每章首帧中央从空白开始；章内换屏不等于换场。沿用仍有用的对象和布局，作用结束的元素退场；独立新场景清除无关旧信息，不一律清空重建。不得提前摆出尚未讲到的结论。
5. **控制注意力。** 一次一个主动作，通常只保留两三个需同时理解的信息组，同一时刻推进的新对象不超过两个。并列例子通常同位替换；需要同时比较时允许并置。显杂时先删，避免重复图形、标签或装饰。
6. **结果留够时间。** 关键结果从动作完成起至少保留 1.5 秒，通常 1.5～2 秒，可与后续解释重叠。优先缩短动作和调整衔接，不抢词，不为清场增加停顿；无人声间隔上限仍为 1.8 秒。

## 版式与颜色

- 背景 `#080A10`；暖白 `#E9E6DC`；辅助说明 `#687484`；背景结构 `#3E4856` / `#26303E`。琥珀 `#E0A24C` 表行动、正向与保留，红 `#C45442` 表损失、否定与错误，绿 `#709670` 表通过与验证。
- 同一场景中颜色、虚线和标记的含义稳定；关键区别同时靠形状、位置、动作或短标签表达。并列项优先靠位置和名称区分。
- 图形与标签用思源黑体 Medium。不用渐变、阴影、圆角等装饰；物体、人物和界面用统一的简化造型与线条。必要的取景变化服务于理解，不代替状态或关系变化。
- 布局优先选单主体、左右对比、上下对比、操作区与结果区等模板；主体、内部内容、标签和连线端点按相对锚点计算。可手写坐标，但不各自独立估位；同一关系沿用位置与尺度。默认整体居中，按任务调整平衡，内容止于 y=860。
- 1920×1080 推荐重要标签 40～48px、辅助标签 32～36px、关键线条 3～4px；在 960×540 预览中主体、标签、断裂和方向仍须清楚。文字与图形、连线互不遮挡，当前重点明于辅助内容；不缩小整图塞信息。
- 对比先明确共同条件、主要变量和结论，保持可比较的位置、尺度与方向。数值和方向与原文一致，不增加无来源的刻度或比例。
- 底部字幕单行居中，楷体 52px、距底 84px；整句约 0.2 秒渐显并保持暖白，不逐字高亮、变色或移动。`【】` 不显示也不触发变色。一屏建议 10～18 字，上限 21，行尾标点隐藏，中文句中不用空格。
- 中央图形可配短标签；整句已在中央展示时用 `无字幕` 关闭底部字幕，适用于短句、论断或开篇，采用楷体与约 0.2 秒渐显，退场后恢复底部字幕。避免中央复刻长段台词。

## 分镜流程

1. **分章与论证骨架。** 写清每章论点、前提、转折、结论和需要看见的关系；选择表达方式及可选母题。
2. **声音与字幕。** 完成朗读稿、演出稿、配音、对稿和切屏，再按实际声音安排画面；声音输入未变时复用已有素材。
3. **逐场景设计。** 列出对象、含义、初始状态、布局锚点及必要变化；不需变化就保持。场景按独立论证划分，不按屏数或动作数硬切。
4. **逐屏分镜。** 写明下表内容并自检；可写“保持，无新增或删除”。仅必要动作绑定触发词，时码供定位，实现读逐字时间戳。
5. **实现与验收。** 写 `画面.tsx`，核对分镜与实现一致，完成技术、布局、动态及理解检查，记录见[开发与导出检查](../开发与导出检查.md#画面验收与版本记录)。

| 原文 / 屏号 | 此前可见 | 保持或变化、用途与触发词 | 观众应理解的关系 | 暂不可见、删除 / 退场与衔接 |
|---|---|---|---|---|

理解目标须能从预览中核对，不能以“分镜写了”代替看懂。对比场景另注明共同条件、主要变量和比较结论。

逐步制作先确认分章与论证骨架（母题可选），再逐章制作。分镜默认由 Agent 自检后直接实现、检查并打开预览，用户看预览后确认本章；仅用户本次明确要求先审分镜时才停在分镜阶段。全自动不增加逐章确认。

## 表达示例

| 原意 | 容易增加猜测的画法 | 更直接的候选 |
|---|---|---|
| 收藏后没有阅读 | 收藏槽连向出口，断线表示未学习 | 简化手机界面：收藏按钮点亮，文章仍标未读 |
| 只能想起零碎关键词 | 无名碎片变红、聚散 | 有名称的知识卡只剩少量内容，错误项用标记或短标签说明 |
| 反复收藏暂缓焦虑 | 多种颜色的节点不断变形 | 明确命名的“焦虑—收藏—暂时缓解—再次焦虑”回路 |

示例只供选择，不自动套用；原文没有的案例或信息不得补入。关键帧看对象能否指认，连续片段看变化与关系能否理解，具体判据见验收文档。

## 处理稿与实现

```markdown
## 02-1 方向
人常有一种恐惧 | 画面:路径/展开
恐惧自己正在努力的方向是错误的
担忧如果方向错了 | 画面:路径/未知
```

- `画面:节/步` 只写必要的视觉节拍，可与 `停留`、`主旨`、`无字幕` 并列；没有新标记时延续状态或已定义动作，不要求新增动作。
- 章节自带 `画面脚本.md` 与 `画面.tsx`，先分镜后实现。导出 `Scene: React.FC<{ cues: SceneCue[]; total: number }>`（类型见 `engine/src/script/scene.ts`）。
- 用 `sceneCtx(cues, useCurrentFrame())` 取状态：`ctx.p("节", "步")` 取进度，`ctx.word(cue, "词")` 取开口帧，`ctx.cueWith("台词片段")` 找屏；不写死台词对应秒数。
- `ctx.at` / `ctx.p` / `ctx.cueOf` 的节拍参数写字面量；组件引用的节拍须在 `script.md` 有对应标记。`ctx.p` 找不到时会停在 0，须由 `check --ready` 核对。只用 `ctx.word` 驱动的标记不要求反向引用。
- `sceneKit.tsx` 的 `P / Box / Dot / Txt` 是可组合的基础图元，不是表达范围限制；可在章节实现物体、人物、界面与相对布局组件，沿用 `MOTION` 色板与字体。
- 有 `画面.tsx` 时优先使用；没有时，程序仅支持下表的现有类型与阶段。新表达方式在章节组件实现，不把未支持的类型直接写进通用标记。

| 现有类型 | 可用阶段 |
|---|---|
| 标题 | 入场 |
| 路径 | 展开、未知、让开、分叉 |
| 概率 | 刻度、概率、遮罩 |
| 时间轴 | 轨道、徘徊、冲刺、结余 |
| 闸门 | 错误、过闸、资源 |

现有通用场景是可选实现，其固定数字和关系不能套到其他原文。V1 至少需要 `画面.tsx` 或有效画面标记，但这只是技术门槛；自动准备的 ArticleScene 摘句与阅读进度不代表正式制作完成。

## 检查与维护

- `npm run check -- NN-M --ready` 查稿件、声音、字幕与节拍等技术条件；`npm run studio -- NN-M` 带真实配音连续验收。静态抽帧不能代替动态和理解检查。
- 每章记录漏画、过画与误解原因；通用结论更新规范。同一组件被三章以上复用时再考虑沉淀到 `sceneKit`。
- 实现位置：`engine/src/style/motion.ts`（样式）、`script/motion.ts`（通用状态机）、`kit/MotionStage.tsx`（通用画面）、`kit/MotionSubtitle.tsx`（字幕）、`Episode.tsx`（正式入口），均位于 `engine/src/`。
