# GitHub 备份与恢复

## 保存代码

先检查当前改动，确认待提交文件不包含私人文章、账号信息或凭据，再按需提交和推送。

```powershell
git status
npm test
npm run typecheck
```

仓库地址、分支和标签应使用自己的配置。本地提交不会自动上传，推送前应再次核对目标远程仓库。

## 素材备份

以 `.gitignore` 为准：依赖、临时文件、`backup/`、各级 `out/`，以及未跟踪的配音、视频、原始 docx、图片和字体等不会随普通提交上传。已经跟踪的文件不受新增忽略规则影响。

私人文章、稿件、字幕、制作记录和媒体应单独备份。只克隆仓库不能保证恢复全部预览和渲染素材；Git bundle 也只保存 Git 历史，不保存忽略的文件。

## 恢复环境

克隆自己的仓库后，在项目目录运行 `npm ci`，再补齐 Python、TTS、ASR、FFmpeg、浏览器和所需素材。制作前阅读 `CLAUDE.md` 与 `docs/风格/README.md`。

恢复旧分支或标签前先保存当前工作。分支切换只恢复 Git 跟踪的文件，忽略的素材需从独立备份恢复，不要直接使用强制清理命令。

## 公开前检查

删除工作区文件不会移除 Git 历史中的内容。公开项目时应检查待发布文件及提交历史，必要时从经过清理的文件创建独立仓库。
